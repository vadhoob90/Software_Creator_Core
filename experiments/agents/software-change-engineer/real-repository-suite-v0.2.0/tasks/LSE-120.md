# Make invalid case-insensitive dictionary updates explicit and atomic

`CaseInsensitiveDict` is documented for string keys, but invalid keys currently
fail through an incidental `.lower()` error and a multi-item update may already
have changed earlier entries.

## Definition of done

1. Direct assignment of a non-string key raises `TypeError` with a message that
   explains that header keys must be strings and identifies the received type.
2. `update()` validates the entire incoming mapping or iterable before applying
   any item. If one key is invalid, the dictionary is unchanged.
3. Valid construction, replacement casing, equality, copying, and updates keep
   their existing behaviour.
4. Focused tests cover direct assignment, mapping update, iterable update,
   atomicity, and valid behaviour.
5. Relevant repository tests and style checks pass.

Do not change dependency metadata or weaken existing tests. Work locally and
report actual verification evidence.
